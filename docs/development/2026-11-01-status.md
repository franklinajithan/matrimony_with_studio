## Security and account lifecycle findings

Read-only live metadata/advisor checks confirm healthy Supabase, account lifecycle migration `20261022154857`, and ACTIVE `account-lifecycle` version 2. The branch release document records previous disposable backend acceptance; those experiments were not rerun here. The service-only deletion ledger intentionally denies client access (RLS with no policies); do not add permissive policies to silence that advisory.

Main still has mock deactivation UI; #51 supplies the replacement. Main and #40/#51 have overlapping deletion architectures that must be reconciled rather than enabled together.

Live `discovery_profiles` is a SECURITY DEFINER view. It deliberately projects limited fields and checks publication, suspension, `member_is_active` and `private.account_session_active`, plus connection photo privacy. Do not blindly switch to SECURITY INVOKER: base-table member visibility needs an explicit review first. [Advisor reference](https://supabase.com/docs/guides/database/database-linter?lint=0010_security_definer_view).

Live `resolve_profile_share` only hides photos when privacy equals `hidden`; it still returns photos marked `connections` to anyone holding a share token. It also lacks the active/suspension predicates used by discovery. This needs a focused privacy migration, disposable SQL acceptance, and review of intended public-sharing consent. No share tokens or member data were retrieved. Anonymous execution of this resolver is deliberate for public share links; caller access alone is not proof of a vulnerability.

`assign_member_public_reference` is an internal trigger function with anon/authenticated EXECUTE grants. Revoke direct execution in a reviewed migration. Other authenticated SECURITY DEFINER RPC warnings require per-function authorization review, not blanket revocation. [Advisor reference](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable).

Leaked-password protection is disabled. [Configuration reference](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). `pg_trgm` resides in public; moving it requires dependency review. No live auth settings were modified.
